# 本地训练任务与模型目录（0.2.1源码）

## 使用方式

- L25的256步检查与L26/L27训练都在独立RL Python中运行。任务先登记，再启动真正独立的后台runner；Qt不导入torch。
- 训练时关闭窗口可选择“停止并保存后退出”“保留后台任务并退出”“取消关闭”。保留后可正常退出GUI；重新打开软件，训练面板的任务列表仍显示状态、预算和seed，运行中的任务自动恢复监控，也可选择任务查看日志或请求停止。
- 停止通过任务自己的STOP文件通知训练循环，保存最后模型后结束。遇到断电或外部终止时显示“意外中断”，保留日志和已有检查点，不自动冒充成功或偷偷重新训练。
- L26–28的“本地模型目录”扫描学习目录内模型，也可导入外部模型目录。核验policy.zip与metadata.json hash后显示seed、实际/请求步数、奖励版本、来源与已关联评价。损坏模型仍显示失败原因。
- 关联外部评价时选择实际report.json，旁边必须有controller_snapshot.json。索引同时核对报告控制器指纹与模型/metadata hash；不能只靠相同文件名关联。选择完整验证报告可填入L28的冻结出处，正式运行时还会再次核对当前运行时的控制器指纹。

## 持久化文件

学习目录中的`training/tasks/<32位任务ID>/`包括：

| 文件 | 用途 |
| --- | --- |
| request.json | 不可变训练请求，含预算、seed、奖励声明副本、来源模型、外部Python路径 |
| launch.json / runner.claim | 启动身份与只运行一次的声明，包含PID和进程创建时间 |
| state.json | 原子写入的最近状态、进度和最终结果 |
| events.jsonl / runner.log | 结构化训练事件与完整进程输出 |
| STOP | 该任务专用的正常停止请求 |
| gui-choice.json | 最近关闭选择的记录 |

输出模型仍在`training/runs/...`的新目录中，避免覆盖旧实验；`training/catalog.json`是可重建索引。损坏索引复制备份，原模型/报告不修改。切换或恢复任务不重新开始训练，也不修改当时冻结的奖励声明。

## GUI集成契约

`TrainingPanel.has_active_training()`只判断已登记的独立训练任务。

`prepare_close(choice)`接受`stop/keep/cancel`并返回当前能否关闭。`stop`发送所有待完成任务的专属STOP并等待正常保存；`keep`只允许保留独立训练，doctor/evaluate/replay等普通QProcess仍按正常关闭处理；`cancel`返回False并恢复默认行为。

`shutdown()`默认停止保存；只有明确`prepare_close('keep')`后才保留任务。`abort_close()`与`resume_monitoring()`撤销保留意图、恢复监控，供其他保存失败或取消关闭时调用。选择keep不会提前停止轮询，因此若窗口最终未能关闭，也仍看得见任务。

任务存活判断使用PID加进程创建时间，避免PID复用误认。软件不根据任务记录中的裸PID杀进程。重启后发现已不存在的进程会显示中断，错误启动的日志也可查。

## 已验与边界

真实测试让启动训练的GUI解释器退出，再通过新GUI恢复监控和正常停止，生成有效stopped模型包。评价、回放、鲁棒性任务仍采用受控QProcess；它们不提供“退出后保留”。本地任务管理不是远程集群调度，也不会自动重试失败训练。

主窗口另有真实QMessageBox三选项测试：取消保留当前窗口与任务；保留后新主窗口重连同一任务；停止请求立即返回，由定时重试等待模型保存再关闭。该项覆盖启动阶段0步停止，持续训练后的退出/恢复由独立父进程333步证据覆盖。

该文档对应0.2.1源码；新版wheel/冻结包发布前仍须验证独立运行时包含`rl.task_runner`并复测关闭/恢复流程。
