# L23–L32：强化学习、公平比较与TITA迁移

本篇保留原始课程设计。0.2.0 已提供独立强化学习训练/评价/回放页，以及外部 TITA 仿真配置与检查入口；所需环境、实际验收与未完成活动见 [实现审计](../IMPLEMENTATION_AUDIT.md)。课程L23–L28以独立CPU倒立摆为主；L29–L32为进阶模块。依赖 [传统控制课程](02_FEEDBACK_CONTROL.md) 和 [代码规划](../DEVELOPMENT_PLAN.md)。建议一节50–60分钟，训练等待和课后作业另计。

## 统一前提

- 学生已能运行自己的反馈控制器，理解x/v/theta/omega与推力，并保存一组可重复实验。
- 继续使用同一倒立摆力输入任务。策略看到4维观测，物理端接收±10 N。网络动作若归一化到[-1,1]，由显式适配器乘10，不能把1误当成10 N或重复乘10。
- 课堂练习用42–46；调参与挑选模型用100–119；最终冻结后用10042–10061。正式用例保存明确的非零初始状态，不用全零静置评成功。
- 训练根seed先用0、1、2独立重复；它们控制整条随机序列，不表示每回合只从同三个初值开始。保存训练配置与样本生成规则，不把最终用例喂回训练。
- 正式任务候选为dt=0.02 s、500步、12°、2.4 m；80°自由探索和鼠标位置辅助不混入算法评分。具体过关表现由基线实验标定，不能预先保证训练多少步一定成功。

## L23｜从“写规则”到“让程序尝试”

**前置/时长：** L21；50分钟。新概念只引入观测、动作、回合、策略，不讲神经网络梯度。

**教师提问：** “你写PID时，谁决定下一次推多大？如果程序自己提出动作，我们怎样告诉它这次做得如何？”

**操作步骤：**

1. 加载已完成的PD参考，在同一个非零初态运行并暂停；学生指出输入和输出。
2. 将控制器换成随机动作，每0.02 s选一个[-10,10] N的力；保持物理参数不变。
3. 运行5个完整回合，记录每次存活步数，保留倒下的回合。
4. 对一次回合逐步回放，圈出“看见状态→选择力→得到新状态”。
5. 用口头规则、Python函数和一个未知策略文件分别表示“策略”，解释表示方式不同但角色相同。
6. 写下随机动作偶尔成功几秒是否意味着会平衡，给出理由。

**练习模板（在新增reset钩子完成后使用）：**

```python
import random

def reset():
    # 课堂演示固定随机动作序列，方便同学对照。
    random.seed(7)

def control(state, dt):
    return random.uniform(-10.0, 10.0)
```

**观察/误解：** 一次存活较久不代表掌握规律；这个模板只生成随机动作，不会学习。正式随机基线由运行器提供每回合独立且可记录的动作seed，不能把上面的固定seed示例当完整评估器。

**提示层级：** 先指动画中的输入输出→显示一步状态转移→展示代码。**交付/验收：** 5回合记录和一张观测/动作/策略对应表，能指出策略与环境各负责什么。没有存活时长门槛。

**界面/代码：** 只增加“随机策略”和单步回放；隐藏网络层数与优化器。新增 `lessons/content/L23.json`、`lessons/templates/l23_random.py`，复用 `core/session.py`、记录器；任务DEV-R01，M5。

## L24｜奖励：把目标写成反馈

**前置/时长：** L23、L10；60分钟。新概念为即时奖励、累计回报、任务指标。

**教师提问：** “只奖励杆站着，会不会允许小车一直向边缘跑？只惩罚用力，会不会让程序选择什么都不做？”

**操作步骤：**

1. 先使用基准存活奖励：每个有效step返回1，观察回报随回合长度变化。
2. 对同一份已保存轨迹，分别计算角度偏差、位置偏差和用力；这一步不重新训练。
3. 用下列示例奖励给两份轨迹重新计分，解释为什么排序可能变化。
4. 把用力惩罚增大10倍，预测小动作策略可能更受偏爱。
5. 区分“修改评分后旧轨迹变分”与“策略真的学会新行为”：重新计分本身不会更新策略。
6. 为奖励配置取一个新版本号，把每一项的目的写下来，暂不选择最复杂公式。

**教师计算示例（无量纲比例，候选权重，尚未校准）：**

```python
def reward_parts(state, force_n):
    angle_cost = 0.6 * (state["theta"] / 0.20944) ** 2
    position_cost = 0.2 * (state["x"] / 2.4) ** 2
    effort_cost = 0.02 * (force_n / 10.0) ** 2
    return 1.0 - angle_cost - position_cost - effort_cost
```

**观察/误解：** 高训练回报不自动等于小角度/省力；奖励定义不同的两次训练不能直接比较回报数值。保留统一物理指标单独比较。奖励函数不能借用未来状态或控制器拿不到的隐含答案。

**提示/验收：** 从“一项奖励鼓励什么”提示到两条轨迹手算，再提供公式。学生提交奖励说明、两种计分表和一个可能钻空子的行为。无需证明这组权重最优。

**界面/代码：** 奖励拆分图按需展开，不在第一课显示；`L24.json`、`rl/rewards.py`、`evaluation/rescore.py`为拟增。DEV-R02；在课程页明确“仅重算分数，未训练”。

## L25｜环境接口与第一次训练准备

**前置/时长：** L23–L24；60分钟。新概念为reset/step、动作空间、终止与时间上限。教师先完成独立训练环境配置，学生不用从零排查安装。

**操作步骤：**

1. 用一张表把4个观测、各自单位和1个动作列出。
2. 手动执行一次reset，确认初态非零；执行一步0 N，再看返回值。
3. 运行一次超过角度边界的实验，再运行参考控制器到500步，区别倒下和时间上限。
4. 查看归一化动作-1、0、1分别变成-10、0、10 N；用代码断言映射只发生一次。
5. 对课程环境执行官方接口检查，再进行256步短运行，检查保存/停止通路。
6. 在没有训练依赖的基础版上检查友好提示，确认前22课仍能打开。

**接口练习（未来课程环境工厂完成后）：**

```python
observation, info = env.reset(seed=42)
observation, reward, terminated, truncated, info = env.step([0.0])
finished = terminated or truncated
```

这里的 `env` 由课程提供，不要求新手自己编写动力学。程序循环可用finished结束回合，但包装器必须保留两个原始标志，交给训练库正确处理时间上限。[Gymnasium接口说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)

**提示/验收：** 先显示状态/动作表→逐项解释返回值→给出接口检查报告。学生能解释两个结束原因，提交映射表；256步只验通路，不认定策略已学会平衡。

**界面/代码：** 增加训练环境检测页、协议摘要；`L25.json`、`rl/env_factory.py`、`envs/wrappers.py`、`tests/test_rl_contract.py`。DEV-R03；使用SB3的环境检查接口验证自定义任务。[SB3自定义环境](https://stable-baselines3.readthedocs.io/en/master/guide/custom_env.html)

## L26｜用PPO训练第一个策略

**前置/时长：** L25；课堂60分钟，加独立训练时间。PPO先解释成“收集尝试，适度调整策略，再尝试”，公式推导放拓展阅读。

**操作步骤：**

1. 选择已冻结的存活奖励和 `balance-v1` 训练分布，锁定其他条件。
2. 保存训练前随机/未训练策略的5回合回放作为起点。
3. 用根seed=0启动一个小预算训练，观察环境步数增长和训练状态，不每一步绘制所有环境。
4. 完成后在验证用例100–119上运行确定性策略；保存模型和报告。
5. 保持配置不变增加训练预算，例如从25,600到102,400步，说明步数是起步预算，不是成功保证。
6. 用seed=1、2独立重复，比较结果是否一致；不要只展示最好的一次。
7. 记录若未学会时应先检查动作缩放、初值、终止和奖励，再调整算法参数。

**教师运行骨架（`env`由未来课程工厂创建，非当前可直接粘贴运行的完整脚本）：**

```python
from stable_baselines3 import PPO

model = PPO(
    "MlpPolicy", env, device="cpu", seed=0,
    n_steps=1024, batch_size=64, learning_rate=3e-4,
    policy_kwargs={"net_arch": [64, 64]},
)
model.learn(total_timesteps=25_600)
model.save("policy")
```

PPO可用于连续Box动作；CPU小型MLP适合作为本项目首个训练方案。此配置是待测试起点，不是经过验证的课程最优参数。[SB3 PPO](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html)

**误解/提示：** 训练曲线是采样统计，不是每一回合都越来越好。提示顺序为检查任务契约→检查一个训练回合→最后才调学习率。不要把“奖励没立刻上涨”简单归咎于学生。

**交付/验收：** 三个独立训练run、模型、参数、评价报告；能解释训练与验证的区别。技术通过标准是训练可完成、可停止、可保存和重载；学习效果单独按标定基线评估。

**界面/代码：** 首屏只显示步数/预算、当前状态、验证结果和停止按钮；高级参数折叠。新增 `L26.json`、`rl/train.py`、`rl/service.py`、`desktop/panels/training.py`。DEV-R04。

## L27｜保存、回放、继续训练与奖励对照

**前置/时长：** L26；60分钟加课后实验。新概念为检查点、训练配置、复现、验证集选模。

**操作步骤：**

1. 关闭训练进程，重新从磁盘加载模型，验证其不依赖编辑器里残留的变量。
2. 检查模型包中的观察顺序、动作倍率、环境hash和奖励版本，故意给一个不匹配的配置，确认软件拒绝加载。
3. 用同一组验证用例比较训练结束时与重新加载后的结果；检查是否误开了探索噪声。
4. 如果使用观测归一化，保存统计并在评估时冻结；缺少统计时明确报错。
5. 从一个检查点继续训练，同时另开一次从零训练；区分“继续”与“从零”。不保证中断恢复后与不间断训练逐位相同。
6. 选择L24一个奖励改动做独立对照，保持预算、训练seed组和环境分布不变。
7. 在验证集上选定最终候选，冻结模型和配置；此时仍不打开保留测试集。

**回放练习：**

```python
model = PPO.load("policy", device="cpu")
action, _ = model.predict(observation, deterministic=True)
# action仍是模型的动作单位；环境/适配器负责唯一一次转成牛顿。
```

**观察/误解：** 保存一个zip文件不等于保存整个实验；缺少环境/预处理说明，模型可能“能加载但表现不对”。模型文件来自受信课程或本人训练，不安排运行同学随意转来的未知反序列化文件。

**提示/验收：** 先对比元数据→再看首步动作→最后查训练参数。交付一个可独立重载的模型包和奖励对照报告，能指出哪些条件保持一致、哪些改变了。

**界面/代码：** 模型列表显示版本/来源/验证结果，避免只有无含义时间戳；`L27.json`、`rl/artifacts.py`、`rl/evaluate.py`。DEV-R05。训练与独立评估、多次运行及归一化管理参考 [SB3实践说明](https://stable-baselines3.readthedocs.io/en/master/guide/rl_tips.html)。

## L28｜PID与强化学习的公平比较

**前置/时长：** L22、L27；60分钟。这是核心课程结业课。

**操作步骤：**

1. 冻结PID代码快照、RL模型、参数和协议hash；明确PD加回中与完整PID的名称。
2. 检查双方观测相同、输出均为牛顿、dt/初值/边界相同，没有一方偷偷使用辅助位置输入。
3. 在保留用例10042–10061逐个运行，任何失败回合都入表。
4. 报告完整回合率、存活步数、角度RMS、最大位置偏移、力RMS和饱和比例。
5. 对RL三个训练seed分别汇报，再给出跨训练run的概括；不要把20个回合误写成20次独立训练。
6. 从各方法选一个失败案例，用状态/推力曲线解释其失效过程。
7. 讨论数据量、计算成本、可解释性、调参工作和适用条件，而不是投票“谁更高级”。

**代码任务：** 学生完成报告字段映射，调用未来的统一评价入口，不复制两套评分逻辑。候选结构：

**提示/验收：** 首先找协议差异→再看逐回合→最后看汇总。交付可复查的完整报告、代码/模型引用、两个失败案例。若结果不符合预期，允许如实得出“当前实现下PD更稳”或“当前预算RL还未学会”；科学记录本身属于成果。

## L29｜延迟、噪声和模型变化

**前置/时长：** L28、L20；60分钟。一次只加一个因素。

**操作步骤：**

1. 固定已冻结控制器，重跑基准组。
2. 分别加入1步、2步观察延迟，保持其他因素关闭，记录延迟对应20/40 ms。
3. 关闭延迟，只加角度测量噪声；分开看真实角度和读数。
4. 关闭噪声，只调整一个物理参数，例如杆质量±10%；标为新测试组。
5. 先写预测，再比较数据，解释失败是否来自观测滞后、噪声或动力学变化。
6. 可选重新训练加入随机化，但必须用新验证集及未暴露的测试组评价，不能覆盖原基准结果。

**代码练习：** 用队列理解延迟，队列长度、初始填充规则写进配置；该逻辑放测量适配器，不写进每个学生控制器。L29只介绍设计草案，未实现前不让学生自行拼接可能错一步的队列。

**误解/验收：** 仿真跑慢不等于传感器延迟；参数随机化不保证解决所有实物差异。提交“因素—预测—结果—解释”表和完整场景配置。

**界面/代码：** 增加一个因子选择和一个强度参数，其余高级参数折叠；`L29.json`、测量/延迟包装器、鲁棒性协议。DEV-R07，M7。

7. 根据该项目工具导出策略，并保存输入输出说明和配置，暂不发给实物执行。

**代码任务：** 用配置文件记录外部解释器、仓库提交、任务ID和日志路径。ControlLab通过外部进程启动预定义任务，不把Isaac依赖导入主程序。

**验收：** 可复现环境清单、加载截图/日志、一次受控回放、导出接口表。能说清CartPole的PPO课程与该仓库具体算法不是同一组网络/配置。

**界面/代码：** “外部环境检查→打开仿真→查看结果”三个动作，错误保留完整日志；`L31.json`、TITA profile与只读任务适配。DEV-R09。实际命令以固定提交验证后的脚本为准，不在课程中粘贴未验证的平台命令。

## L32｜迁移报告与实机前检查

**前置/时长：** L29–L31；两节60分钟。本课完成物理机器人部署方案，实机实验是另一个需要硬件条件和现场指导的项目，不作为本计划软件交付的默认动作。

**操作步骤：**

1. 列出模型与真实设备的差异：电机能力、延迟、摩擦、传感器噪声、接触和电源状态。
2. 核对设备型号/系统版本、支持的接口和动作单位，填一份接口表。
3. 在仿真中验证停止指令、消息超时和动作限幅，确认策略进程停止不会继续无限重复最后动作。
4. 制作只读数据采集方案，再制作有现场指导的低风险动作验证方案，说明谁负责停止与观察。
5. 定义进入下一阶段的证据：仿真验证、接口核对、现场测试条件、可执行的停止方法。未满足时停在仿真学习阶段。
6. 汇总从手动到PID/RL的学习记录，选一个仍未解决的问题，制定后续小课题。

**代码任务：** 首先规划遥测读取和日志回放；硬件命令适配器与仿真策略加载器分离。连接参数不硬编码到学生模板，环境不可用时不影响倒立摆课堂。

**验收：** 一份可审查的迁移报告、接口表、仿真停止测试记录与后续实验计划；不要求每个零基础学生在本课让真实机器人跑起来。

**界面/代码：** `L32.json`、遥测回放/报告模板；真正机器人控制作为后续专门开发项，不在M7默认工时中承诺完成。DEV-R10。

## 教师备课资料

PPO公式仅供进阶阅读：[原始论文](https://arxiv.org/abs/1707.06347)。零基础课堂先形成观察、动作、奖励和试验的对应关系，再用裁剪更新的直觉解释为什么不能每次把策略改得过大。本文选择PPO是教学顺序安排，并非声称它在本任务必定优于所有其他连续控制算法；SAC等可作为后续选修，不同时塞进首个RL章节。
