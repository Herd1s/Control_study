# 基础篇：从第一次拖动到第一条反馈规则（L01–L12）

> 规划基线：2026-10-07。本文保留原始课程与开发规格，不作为 0.2.0 完成清单。当前已提供逐课资源和课堂入口；实际可执行活动、教师确认项与未完成细节见 [实现审计](../IMPLEMENTATION_AUDIT.md)，运行方式见 [README](../../README.md)。

## 1. 适用对象与教学原则

面向没有 Python、控制、机器人基础的学生。先有体验，再有名称，再出现代码；不要求先学完整 Python，也不把“会调到一个能平衡的参数”当作唯一学习成果。

- 每课 45–60 分钟，下面建议课时共 640 分钟，约 10 小时 40 分钟。按实际学情可拆成两次短活动。开发者每周 6–8 小时的投入是备课、开发和试讲时间，不能等同于学生每周课时。
- 第一课自由开放，不设置存活排行榜，不用倒下次数惩罚学生；之后的过关主要检查预测、解释和实验记录。
- 全部主线代码输出 **推力 N**。目标速度只放在 L11 支线，明确它借用了软件内部速度控制器。
- 已学内容随时可返回。教师可跳到任一课，不用刚性锁课阻止试讲；系统建议下一课，并保留个人进度。
- 代码错误是课堂素材。允许回退、查看差异、重新运行；不要用红色全屏遮挡动画，也不要直接用答案替换学生代码。
- 用户已要求删除装饰性小字。页面不恢复英文口号、版本号或重复底部提示；保留本课任务、必要按钮、变量名称和单位。指导正文用可读字号，每次只显示当前一步，完整说明放在可展开的“为什么”。

## 2. 课程与软件共用的约定

### 2.1 方向、单位和代码入口

| 量 | 中文含义 | 代码名称 | 单位与方向 |
| --- | --- | --- | --- |
| 小车位置 | 距离轨道中心多远 | `state["x"]` | m，向右为正 |
| 小车速度 | 小车正往哪边、移动多快 | `state["v"]` | m/s，向右为正 |
| 杆角度 | 偏离竖直方向多少 | `state["theta"]` | rad，杆顶向右偏为正；界面可显示 ° |
| 杆角速度 | 杆正在往哪边转、转多快 | `state["omega"]` | rad/s，角度增大为正；界面可显示 °/s |
| 控制输出 | 本步给小车的推力 | `return` 后的数值 | N，向右为正；当前执行器限幅 ±10 N |
| 仿真步长 | 一次物理推进的时长 | `dt` | 0.02 s，与屏幕刷新耗时分开 |

初学者一直使用短函数，不要求创建类：

```python
def control(state, dt):
    return 0.0
```

从 L09 开始，可选提供 `reset()` 以清空累计时间和其他记忆；没有 `reset()` 的无状态旧代码仍然可运行。0.2.0 已提供回合重置协议。高级 `Controller.reset/act` 类留给后续项目组织课，不在本篇要求学生学习。

### 2.2 体验模式与评估模式必须分开

第一课计划采用自然的鼠标位置操纵：鼠标带动小车，模型根据小车运动计算摆杆响应。鼠标抓住车身任何位置都保持原抓取点，不突然把小车中心吸到光标。实现应使用有界且平滑的位置轨迹，并把其速度、加速度耦合到摆杆运动；不能只修改小车绘制坐标或仅改 `x` 而让摆杆不受影响。

这种模式存在操纵帮助，不与后续直接输出 N 的 PID、强化学习比较成绩。松手时连续交接小车速度和摆杆状态，恢复真实动力学；边界处不瞬移，不产生无限加速度。教学引导只需说“这一课用鼠标直接带动小车”，无需向初学者展示实现参数。

**当前差距：** 手拖仍是 `30 × (目标位置 − x) − 8 × v` 的推力跟踪并限制在 ±10 N，存在跟手延迟和点击位置偏移。先修好这一体验，再把 L01 作为学生正式入口。

### 2.3 初态、扰动与时间的约定

- “重新扶正”仍表示 `x=v=theta=omega=0`，保持暂停。理想模型在完全竖直、静止、零输入且没有扰动时可以一直不倒；这不是学生已经学会稳定控制。
- 需要比较控制效果时，明确选择“从轻微右倾开始”“从轻微左倾开始”或“轻推一下”。不要为制造效果偷偷把普通复位改为随机倾斜。
- 初态建议由课程场景声明，例如 `theta=+2°`，进入物理层时转为 rad。外力扰动采用固定方向、幅值、持续步数并记录，例如小车额外受 +2 N、持续 5 个物理步。控制输出和外加扰动分开记录，执行器限幅先作用于控制输出；外力不是学生动作。该能力尚待开发。
- 有记忆的学生程序要求一次 `control(state, dt)` 对应一次固定 `dt` 的物理推进；暂停不调用、不累计，单步恰好推进一次。当前异步 GUI 可以沿用旧输出推进物理，与代码调用数不一致，须先修正再教 L08–L09 的精确时间实验。

## 3. L01：自由拖动，先感受平衡

**前置与课时：** 不要求任何基础；50 分钟（演示 5、自由探索 20、结对观察 15、复盘 10）。正式授课前先完成 DEV-F01；现有手拖可用于教师内部演示，但不把慢跟随当成正确交互。

**只引入：** 小车、摆杆、拖动、松手、重新扶正；不讲变量、公式、PID 或“最优”。

**教师问题：** “杆向右倒的时候，你先往哪边试？”“你是看到它已经倒很多才动，还是提前动？”不给一个必须模仿的鼠标轨迹。

**学生操作：**

1. 看见静止的小车与竖直杆，移动鼠标到车身；出现清楚的可抓取反馈。
2. 在车身不同位置按住并左右移动，确认自己可以操纵，不要求保持多久。
3. 放开鼠标，看小车和杆接下来怎样运动；倒下就点“重新扶正”。
4. 分别试一次“小幅、慢速移动”和“大幅、快速移动”，先说出预测再试。
5. 找到一次觉得“接住了”的瞬间，用暂停保留画面，向同伴描述刚才做了什么。
6. 再自由试 3 次；在课程卡上写一句“我发现……”或口头告诉教师。

**代码：** 不用代码，不展示编辑器。课后也不安排 Python 安装作业。

**可观察结果：** 移动车底会改变杆的倾倒趋势；动作太大可能更难接；松手后运动不会凭空消失。现象受当前角度、速度等共同影响，不把“向右拖就一定向右倒”写成固定结论。

**误解与分层提示：**

- “杆站着没动，说明我控制成功了。”提示 1：“刚才你给它输入了吗？”提示 2：“理想模型完全不动时可以暂时保持竖直。”提示 3：邀请学生先轻轻移动小车再开始观察。
- “快速来回甩总能救回来。”提示 1：回看一次失败；提示 2：比较小动作和大动作；提示 3：教师只演示一次提前的小修正，不提供唯一操作方式。

**交付与过关：** 记录一个有帮助的动作和一个容易失败的动作；能独立抓取、松手、重新开始。无需达到指定平衡秒数。系统只能记录已体验的动作，解释质量由学生自评或教师判断。

**界面显示：** 画布、单句当前任务、暂停/继续、重新扶正；拖动时有轻量轨迹或方向反馈。不显示数值、分数、参数滑块、代码、曲线和后续未完成模块按钮墙。

**软件与文件计划：** DEV-F01 自然拖动与松手交接；DEV-F03 逐步引导及探索式完成卡。课程配置 `lessons/content/L01.json`；新增 `tests/test_manual_input.py` 验证抓取偏移、边界和速度交接；功能代码位置以总代码规划为准。

## 4. L02：复位、暂停与外力扰动

**前置与课时：** 完成 L01；50 分钟（回顾 5、三种操作 15、对照实验 20、复盘 10）。

**只引入：** 一次尝试/回合、复位、暂停、继续、外力扰动、相同起点。不介绍随机种子、能量或力学推导。

**教师问题：** “暂停和扶正都会让画面停住，它们有什么不同？”“两个人从不同倾角开始，能直接比较谁坚持得久吗？”

**学生操作：**

1. 普通扶正后保持零输入，观察完全竖直静止的初态。
2. 用鼠标产生运动，点击暂停；确认暂停保留当时位置和倾斜。
3. 点击继续，观察运动接着发生；再扶正，确认四个物理量回到零。
4. 选择“轻微右倾开始”场景，软件明确显示这一课人为设置了轻微倾斜；开始后先不控制。
5. 扶正并切回“完全竖直”；点击“轻推一下”，看短暂外力怎样打破静止。
6. 使用同一个轻推场景重复两次，一次早动手，一次晚动手，描述差别。
7. 保存或填写两条实验卡：起点/扰动是否相同、自己何时动作、结果怎样。

**代码：** 不用代码；场景和扰动由界面按钮提供。教师不要求学生手改物理对象。

**可观察结果：** 暂停保留状态且仿真时间不增长；复位重新开始；非零初态或外力会使理想竖直状态发生变化。两次相同输入场景具有可重复起点。

**误解与分层提示：**

- “扶正后应该自己慢慢倒。”提示 1：检查是否有扰动；提示 2：解释这是没有空气晃动等因素的理想模型；提示 3：主动选择可见的轻推场景。
- “暂停就是把速度变成零。”提示 1：继续后观察；提示 2：暂停只停止时间推进；提示 3：对照复位动画和当前状态。
- “轻推就是我的程序动作。”提示 1：看扰动箭头；提示 2：区分“我施加的控制”和“外界推了一下”；提示 3：在记录中用两列分开它们。

**交付与过关：** 正确说明复位、暂停和外力的不同；能让两次实验从同一场景开始。固定场景重复检查可自动化，解释用两道短问答完成。

**界面显示：** 增加场景选择卡和“轻推一下”；外力只在施加时显示方向箭头。仍不出现四张传感器卡或 Python。普通扶正与“带初始倾斜的试验”按钮名称必须不同。

**软件与文件计划：** DEV-F02 可声明初态、固定外力事件和记录；DEV-F03 课程选择卡。`lessons/content/L02.json`；场景数据 `lessons/scenarios/foundation.json`；场景测试覆盖重复性、暂停期间不消耗扰动步数、普通扶正仍为全零。

## 5. L03：位置不等于速度

**前置与课时：** 完成 L02；55 分钟（引入 10、体验 20、预测卡 15、复盘 10）。

**只引入：** 轨道中心、向右为正、位置 m、速度 m/s；先中文后出现 `x`、`v`。暂不讲导数。

**教师问题：** “小车在右边，就一定还在向右走吗？”“两个时刻小车都经过中心，后续会一样吗？”

**学生操作：**

1. 扶正后只打开“位置”读数，找出中心 0 m，慢拖到左右两边。
2. 暂停在右侧，说出位置符号；松开鼠标，不用“右边”替代“正在向右”。
3. 打开“速度”读数，观察同一位置附近朝两个方向移动时符号不同。
4. 完成一段“小车在右侧但向左运动”的轨迹并暂停，保存为例子。
5. 观看两个预置短回放：都经过中心，一个向左、一个向右；先判断速度符号再揭示读数。
6. 在位置随时间曲线上找一段上升、一段下降、一段近乎水平，结合动画解释。
7. 完成三张预测卡：右侧向左、左侧向右、中心静止，分别填位置和速度的符号。

**代码：** 不用代码。变量名称显示在中文名称旁，学生不需要记忆字典语法。

**可观察结果：** 位置说明“在哪里”，速度说明“怎样移动”；`x>0` 可以同时有 `v<0`；曲线是否向上与当前速度方向相关，而不是与位置正负绑定。

**误解与分层提示：**

- “位置为零就没有在动。”提示 1：看经过中心的回放；提示 2：中心只是位置参考；提示 3：同时框出 `x≈0` 和非零速度。
- “负速度比正速度更慢。”提示 1：只比较 0.5 和 −0.5 的移动距离；提示 2：符号表示方向；提示 3：显示两段同样时长、相反方向的回放。

**交付与过关：** 保存一张 `x>0、v<0` 的场景卡；三张预测卡至少两张正确，错题可以回放后重做；能用一句话区分位置与速度。

**界面显示：** 仅位置、速度两张读数卡；位置曲线默认折叠，完成前四步后再出现。隐藏角度、角速度、代码和输出模式选择。

**软件与文件计划：** DEV-F03 按课解锁读数；DEV-F04 同步时间游标、短回放和预测卡。`lessons/content/L03.json`；预置回放由固定输入离线生成并附场景配置，不能手画伪数据；`lessons/scenarios/foundation.json` 增加本课样例。

## 6. L04：角度不等于角速度

**前置与课时：** 完成 L03；55 分钟（旧知识连接 5、体验 20、对照 20、复盘 10）。

**只引入：** 竖直为 0°、左右倾斜、角速度 °/s；界面角度与代码 rad 的单位不同。暂不要求背三角函数或推导角速度。

**教师问题：** “杆现在向右倾，就一定正在向右倒吗？”“倾斜相同但一个正在回正，应该采取完全一样的动作吗？”

**学生操作：**

1. 打开角度卡，扶正看 0°；用鼠标形成左右倾斜，看正负号与虚线竖直基准。
2. 暂停并沿杆画出倾角弧线，确认角度取自竖直而不是水平轨道。
3. 打开角速度卡，观察角度越来越大和越来越小的时刻。
4. 播放两段同角度、不同角速度的预置片段，暂停比较箭头和读数。
5. 找到“仍向右倾、已经往回转”的瞬间，描述此时角度正、角速度负。
6. 点开“代码里如何表示”，看一次 5° 与约 0.0873 rad 的对应；不要求心算换算。
7. 给“当前倾斜”和“倾倒趋势”各写一句自己的解释，再预测两段片段哪段更紧急。

**代码：** 不用代码。后续看到 `theta` 和 `omega` 时能对应含义即可。

**可观察结果：** 倾斜方向和转动方向可以不同；同一角度不是同一状态；四个读数一起描述小车和杆的运动。

**误解与分层提示：**

- “角速度就是角度除以总时间。”提示 1：回看角度先增大后减小；提示 2：关注这一小段时间的变化；提示 3：相邻两帧角度差对应当前变化趋势，精确计算留到后续。
- “`theta=5` 就是 5°。”提示 1：查看变量旁单位；提示 2：代码使用 rad；提示 3：使用界面换算卡，强调 5 rad 不是小倾斜。

**交付与过关：** 正确区分四种读数的含义和单位；识别同角度但不同角速度的两个场景。无需计算导数。

**界面显示：** 本课按顺序增加角度弧线、角度卡、角速度卡；其余两卡可以收起。一次曲线只突出一种量，避免四条不同单位的曲线共用同一纵轴。

**软件与文件计划：** DEV-F03 逐步显隐；DEV-F04 同角度对照回放；DEV-F05 单位与符号一致性检查。`lessons/content/L04.json`；场景生成器保留真实 `theta/omega`，渲染测试核对向右倾与正角度一致。

## 7. L05：让第一条推力指令动起来

**前置与课时：** 完成 L04；50 分钟（演示 10、三个数实验 20、独立操作 10、复盘 10）。

**只引入：** 数字、正负号、小数、`return` 返回动作；`def control(state, dt):` 暂作为软件约定的固定外壳，不展开全部函数语法。

**教师问题：** “代码怎样表达向右推？”“零推力是否等于把运动强行停止？”

**学生操作：**

1. 进入固定“推力 N”模式，看到只需修改一个数字的模板；先读当前场景为全零初态。
2. 预测 `return 1.0` 的推力方向，再运行一个短观察片段，例如 0.2 秒后自动暂停。

## 11. L09：让程序记得时间，并正确重置

**前置与课时：** 完成 L08 且 DEV-F06 已通过验证；55 分钟（引入 10、填空 20、重置实验 15、复盘 10）。

**只引入：** 跨调用记忆、`+=`、模块变量、`global`、可选 `reset()`；不引入类或积分控制。先累计时间，为以后累计误差打基础。

**教师问题：** “每次都把计时器设为零，它还能记住多久吗？”“第二次运行应该接着上次的时间，还是从头开始？”

**学生操作：**

1. 打开已写好函数外壳的模板，先只阅读“累计到约 0.5 秒停止推力”的任务。
2. 在 `control` 里补上 `elapsed += dt`，通过单步观察 0.02、0.04 等累计值。
3. 从全零初态运行，观察先推后停止给力；停止给力后小车仍可能继续运动。
4. 暂停较长一段真实时间，再继续，确认暂停期间仿真计时没有偷偷增长。
5. 执行“重新实验”，确认系统调用 `reset()`；第二次动作序列与第一次相同。
6. 在隔离演示中把 `elapsed = 0.0` 错放到 `control` 开头，预测并观察“永远记不住”的问题，再恢复。
7. 保存正确版本，并说明普通暂停、重新实验、修改代码重启各自是否清空记忆。

**规划中的模板：** 使用已学过的 `if`，不同时引入新的条件表达式或类。

```python
elapsed = 0.0


def reset():
    global elapsed
    elapsed = 0.0


def control(state, dt):
    global elapsed
    force = 0.0
    if elapsed < 0.5:
        force = 1.0
    elapsed += dt
    return force
```

在当前 `dt=0.02` 下，此例前 25 步输出 1 N，随后输出 0 N。这里只学习“记住上次的值再累计”，不教授浮点计算细节；软件显示时间取自整数步数乘步长。以后需要精确扰动时刻或停止边界时，由场景事件使用整数步数调度，不能假定任意小数累计都可作精确计时器。

**可观察结果：** 记忆在同一回合跨调用保留，复位后回到零；物理时间由 `dt` 累计，独立于真实暂停时长。系统重新加载代码本身也会重建变量，但课程要求显式 `reset()` 以便未来复用会话时行为一致。

**误解与分层提示：**

- “全局变量太复杂，必须先学面向对象。”提示 1：只说明“函数外的小记事本”；提示 2：`global` 允许本函数修改那本记事本；提示 3：提供固定外壳，只填写累计那一行。
- “停止推力等于刹停。”提示 1：看速度；提示 2：回到 L05 的零力实验；提示 3：让学生提出以后怎样加一个主动减速阶段。
- “暂停后重新从零计时更方便。”提示 1：看同一回合是否被保留；提示 2：暂停不应改控制器状态；提示 3：对照“重新实验”按钮。

**交付与过关：** 能解释把累计值放在函数内部重置会发生什么；连续两次新回合动作序列一致；暂停不增加时间。自动检查依据控制步序列，不依据真人按按钮的墙钟时刻。

**界面显示：** 增加一项“本回合累计时间”和可展开的记忆说明；保留单步；不要同时展示积分误差、Ki 或 PID 曲线。

**软件与文件计划：** DEV-F06 worker 支持可选 `reset()`、异常回报与生命周期；DEV-F07 测试新回合/暂停/热重载语义。`lessons/content/L09.json`、`lessons/templates/l09_timed_push.py`；重置语义测试覆盖无 `reset()` 老程序、`reset()` 报错、旧回复丢弃和从完全相同初态重复运行。

**界面显示：** 新增本地实验列表、两条同单位曲线、时间游标和“定位错误”；默认只呈现与当前任务有关的轴。详细原始回溯放折叠区，不能隐藏真正异常信息。

**软件与文件计划：** DEV-F04 曲线回放与同时间比较；DEV-F08 错误定位与提示；DEV-F09 本地实验包、代码快照、配置与结果关联。`lessons/content/L10.json`、`lessons/templates/l10_debug_direction.py`；学生记录写到用户数据目录，不写安装目录；已有 CLI CSV/JSON 不等于桌面实验库已经实现。

## 13. L11（支线）：目标速度与推力的区别

**前置与课时：** 完成 L08，建议在 L10 后学习；50 分钟（概念 10、对照 20、解释 10、回主线 10）。不学本课也能继续 L12 和 PID。

**只引入：** 动作单位改变会改变含义；目标速度由隐藏在软件中的速度反馈环转换成力；不重新讲一次 Python 函数，也不把该帮助环当成学生已学会的 PID。

**教师问题：** “同样返回 0.5，软件到底答应了什么？”“要求速度为零，与给零推力会有一样的刹车效果吗？”

**学生操作：**

1. 在推力模式运行固定 `0.5`，记录单位为 N，观察小车速度随状态变化。
2. 停止并复位，切换为目标速度模式；界面醒目显示 m/s，提示本课有软件帮助控制。
3. 使用同样的 `0.5`，观察软件根据速度差持续调整实际推力；不能只看返回值。
4. 从同一个移动初态分别比较推力模式的 `0.0` 和速度模式的 `0.0`。
5. 试小幅正负目标速度，指出“目标”和“当前实际”可以不同，达到力限幅时不可能瞬间跟上。
6. 用两句话解释这两个模式，切回推力 N 并新建一次主线实验；旧记录仍保留原动作单位。

**两份模板：**

```python
# 推力模式：这表示 0.5 N。
def control(state, dt):
    return 0.5
```

```python
# 目标速度模式：这表示目标 0.5 m/s。
def control(state, dt):
    return 0.5
```

当前桌面内部转换为 `F = 8 × (目标速度 − 当前速度)` 并限幅 ±10 N，系数单位为 N/(m/s)。这是现有实现说明；学生界面先用箭头图说明“目标速度 → 软件调节推力 → 小车”，后续可展开公式。

**可观察结果：** 速度目标不等于实际速度保证；零速度指令会让软件尝试减速，零力不这样做；对同一动作数值，单位不同会产生不同实验。

**误解与分层提示：**

- “速度模式效果好，所以我的代码比推力 PID 更好。”提示 1：查看软件帮助标记；提示 2：此模式额外用了速度反馈；提示 3：公平比较需统一动作定义，不能直接合并分数。
- “模式切换后旧代码意义不会变。”提示 1：看单位；提示 2：数字相同而指令含义不同；提示 3：停止、重新确认、作为新实验运行。

**交付与过关：** 正确解释两个 `return 0.5` 和两个 `return 0.0` 的差异；能从保存记录中读出动作模式。该课不能给直接力控制的平衡成绩加分。

**界面显示：** 只在支线开放模式选择；并排展示目标速度、实际速度、实际推力，速度与力用独立坐标或切换标签。离开支线明确恢复 N，不能静默沿用 m/s。

**软件与文件计划：** 当前两种模式转换已有；DEV-F05 模式/单位持久化与切换确认；DEV-F09 记录内部速度环配置并排除跨模式排名。`lessons/content/L11.json`、`lessons/templates/l11_target_velocity.py`；模式切换不得覆盖原代码，须停止旧会话并创建新实验。

## 14. L12：写第一条角度反馈规则，走向 P

**前置与课时：** 完成 L01–L10；L11 可跳过；55 分钟（回忆体验 10、编写 15、比较 20、总结 10）。

**只引入：** 读角度、乘以可命名系数、误差越大动作越大；最后才给这个规则命名为比例反馈 P。不在同一课加入角速度、积分、回中和自动调参。

**教师问题：** “杆快向右倒了，车底应该往哪边去接？”“每次都用同样大小的力，和根据倾斜大小改变力，有什么区别？”

**学生操作：**

1. 回看 L01 的一次接杆瞬间，再用两个静态角度卡判断控制方向；强调角度任务与 L07 位置回中方向不同。
2. 用 `angle = state["theta"]` 取本次角度，先只填写 `force = 10.0 * angle`。
3. 在“试算一次”卡输入 `theta=+0.02 rad`，预测约 +0.2 N；再用 −0.02 rad 预测相反动作。
4. 使用明确的轻微右倾/左倾初态运行，观察规则能够响应，但不承诺稳定平衡。
5. 固定同一场景，把系数从 10 改为 30，再改为 60；每次只改这一个数字并保存曲线。
6. 将系数命名为 `gain`，标注单位 N/rad；比较角度响应、是否来回摆、是否碰到 ±10 N 限幅。
7. 选出一段 P 控制仍失败的片段，提出“除了现在偏多少，还缺什么信息”，连接下一课角速度和 D。

**模板与练习：**

```python
def control(state, dt):
    angle = state["theta"]  # rad，向右倾为正
    gain = 10.0             # N/rad，先从这个值开始试
    force = gain * angle
    return force
```

这里定义的角度偏差就是 `theta - 0`，因此向右倾时给向右推力去接杆。以后若改用“目标减测量”的误差定义，符号也要一起调整；不能机械套用负反馈符号导致方向反了。

**可观察结果：** 输出随倾角连续变化；零角度时本规则给零力，但杆可能仍有角速度，所以零角度不等于“无需动作”。更大系数可能更快也可能增加振荡或饱和，不保证单调改善。

**误解与分层提示：**

- “所有正反馈量都应该乘负数。”提示 1：回到物理接杆方向；提示 2：不同测量和误差约定的符号不同；提示 3：用 ±0.02 rad 的试算验证。
- “增益越大越好。”提示 1：看是否频繁达到推力上限；提示 2：同时看来回摆动；提示 3：保存小/中/大三组完整轨迹，不只比较一瞬间。
- “P 没成功说明 PID 也没用。”提示 1：找两段同角度不同角速度的片段；提示 2：当前规则没读运动趋势；提示 3：带着问题进入 PD 课，而不是直接给参考答案。

**交付与过关：** 一份角度比例代码、3 个增益的同场景实验、一段失败说明；能预测固定角度下动作的方向与大致大小，能说出 P 的输入是什么。不要求仅凭 P 完成 10 秒稳定平衡。

**界面显示：** 默认只显示角度与推力两项；比较时打开相应曲线。任务完成后用一张简短概念卡命名“比例反馈 P”，后续 D/I 按需出现。

**软件与文件计划：** DEV-F02 固定非零初态；DEV-F05 rad 与 N 保持一致；DEV-F07 数值试算；DEV-F09 三次对照记录。`lessons/content/L12.json`、`lessons/templates/l12_angle_rule.py`；测试核对正负角度的作用方向、动作限幅与记录中的未限幅/实际值。
