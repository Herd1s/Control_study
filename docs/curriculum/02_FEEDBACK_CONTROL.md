本文保留原始课程与实现规格，面向已经完成 L01–L12 的学生。0.2.0 已有传统控制面板、独立小车速度场景和正式评价；逐项可操作范围、尚未完成的活动及验收证据见 [实现审计](../IMPLEMENTATION_AUDIT.md)，运行方式见 [README](../../README.md)。下文设计要求不等于所有细节都已完成。

## 教学约定：先观察，再命名，再写代码

每课只增加一个主要概念。先让学生预测，再运行，再比较，最后给现象命名。建议本阶段安排约 14–18 小时，允许拆为 45 分钟的小课；课时包含观察、改代码、讨论和记录，不按观看动画的时间计算。

所有倒立摆代码统一使用推力模式，`control(state, dt)` 返回 N。不要在 P/PD/PID 课悄悄切换到目标速度模式，否则软件内部已有的速度控制环会改变实验对象。四个观测量固定为：

| 字段 | 含义与单位 | 正方向 |
| --- | --- | --- |
| `state["x"]` | 小车位置，m | 向右 |
| `state["v"]` | 小车速度，m/s | 向右运动 |
| `state["theta"]` | 杆相对竖直方向的角度，rad | 杆向右倾 |
| `state["omega"]` | 角速度，rad/s | 向右倾的角度正在增大 |
| `dt` | 固定物理步长，s | 当前为 `0.02`，与屏幕刷新耗时无关 |

界面可显示角度 °，代码始终使用 rad。`theta = 0.05 rad` 约为 `2.86°`，不能把界面的 `2.86` 直接代入按 rad 整定的增益。

现有参考控制器在直立附近使用：

```python
force = 60.0 * theta + 12.0 * omega + 2.0 * x + 3.0 * v
```

这些数字来自项目当前参考实现，是课堂对照起点，不承诺对任意初始状态、噪声、负载或机器人都稳定。默认积分系数 `Ki = 0`，因此实际是角度 PD 加小车状态反馈。教学中不能为了凑齐 PID 三个字母而强行增加积分。

符号必须先用动画校验：杆向右倾时，需要向右推动底座去接住杆，所以以 `theta - 0` 为角度误差时比例项为正。小车回中项 `+2x + 3v` 属于整套耦合倒立摆反馈；它不是把小车作为独立物体时常见的 `-Kx*x-Kv*v`。这一差别是 L16 的重点。

### 实验记录与两种使用场合

- **自由观察**：保留当前课堂 80° 倒下阈值，可以慢放、暂停、尝试大动作；不与正式成绩混用。
- **正式比较**：统一 `dt=0.02 s`、推力限幅 `±10 N`、角度阈值 `12°`、位置阈值 `2.4 m`、每回合最多 `500` 步，即 `10 s`。所有被比较控制器使用相同环境版本、相同初始状态、相同种子与相同外扰。
- **统一种子分组**：课堂练习使用 `42–46`，开发/调参验证使用 `100–119`，最终评分使用保留的 `10042–10061`，共 20 回合。评分前冻结代码和参数；不能一边看最终评分结果一边继续调参。最终以课程工程的中央评估协议为准；同一个协议不得由各课自行改动。
- 当前桌面“重新扶正”将四个状态归零。理想模型在全零状态与零输入下不会自动倒下，因此“原地静置 10 秒”不能作为控制通关证明。正式比较使用有非零初始状态的回合；GUI 需要新增明确的“测试初始偏差”与“施加扰动”入口。
- 现有 `make_env().reset(seed=...)` 已能生成可复现的初始小扰动。本文部分课堂给出精确初始状态，属于拟新增的场景配置能力，不让新手直接修改 `env.unwrapped.state`。
- 每次保存代码快照、参数、环境配置、种子、实际初始状态、运行状态和轨迹。正式协议拒绝全零初态，并保存每个 case 的显式初始状态及配置哈希。现有命令行已记录其中一部分；补齐字段及批量比较属于后续开发工作。

精确课堂初始状态写作 `[x, v, theta, omega]`，顺序不可更换。新加的实验控制面板应提供中文字段名和单位，不要求学生第一次就输入数组。

## L13：倒得越多，就推得越多——比例 P 与方向

**前置**：会修改 `return`、读取 `state["theta"]`，理解正负方向；不要求微积分。建议 60–75 分钟。

**引导问题**：“杆稍微向右倾和明显向右倾，应该给同样大小的推力吗？”

**课堂步骤**：

1. 暂停在 `theta=+0.05 rad` 的初始画面，让学生先画出小车应移动的方向。再换成 `-0.05 rad`，确认答案反向。
2. 用已学的条件控制作为起点，例如 `theta>0` 就给 `+1 N`，否则给 `-1 N`。记录小角度和较大角度时动作都一样的局限。
3. 把条件改成乘法 `force = kp * theta`。先不给 P 的英文缩写，称为“偏得越多，推得越多的规则”。
4. 手算 `kp=60`、`theta=0.05` 时输出 `3 N`；先在预测框写下答案，再按单步验证。增加“符号×大小”的力箭头。
5. 比较 `kp=20、40、60` 三次实验，只改一个数字，每次重置到同一非零初始状态。
6. 在复制出的错误案例里试一次 `-kp*theta`，观察与预测是否一致，立即恢复正确符号；不把“失败越快”作为学生能力评价。
7. 最后才介绍“比例反馈 P”，学生写一句“它看什么、返回什么、正负号为什么这样选”。

**学生代码**：

```python
kp = 60.0  # 课堂参考起点；单位 N/rad

def control(state, dt):
    theta = state["theta"]
    force = kp * theta
    return force
```

**实验条件与对照**：先固定 `[0, 0, 0.05, 0]`，再做镜像 `[0, 0, -0.05, 0]`；比较固定推力规则与 P。短时观察允许失败，不要求仅靠 P 长期稳定。代码返回请求力，环境再限幅；同时记录两者。

**常见误解**：`kp` 不是推力本身；角度 0.05 不是 0.05°；零输出不等于小车会立即停止；把所有反馈写成“目标减实际”后仍沿用原正号，会改变控制方向。

**界面显示顺序**：先保留动画与左右箭头 → 只亮起角度读数 → 显示请求推力 → 显示一行乘法 → 最后出现 `P` 标签。暂不显示积分和其他增益面板。

**验收与产物**：正确预测正负初始倾角的第一步推力；完成 3 行参数—现象记录；提交 `l13_p.py` 与一句符号解释。存活时间不作为本课硬门槛。

**拟实现模块**：`src/control_lab/lessons/content/L13.json` 的引导与镜像初始条件、`lessons/templates/l13_p.py` 代码模板；复用统一场景执行器与“单步预测”组件。对应测试：镜像状态的 P 输出反号，界面 rad/° 标签不混用。下文短路径均相对于 `src/control_lab/`。

## L14：为什么调大参数也会失败——扫描、振荡与饱和

**前置**：完成 L13，能只修改一个变量。建议 60–75 分钟。

**引导问题**：“推得更猛，是否一定更稳？怎么区分‘调得不好’和‘这个规则缺信息’？”

**课堂步骤**：

1. 重放 L13 的一次失败，暂停在杆越过竖直的时刻，询问小车或杆是否还在运动。
2. 填写预测表：`kp=0、20、40、60、100` 中，哪些可能反应不足，哪些可能出现大动作。只做预测，不把排序当答案。
3. 逐个运行同一初始条件，记录首次失败原因、最大偏移和推力是否触顶。先手动运行三次，再展示批量扫描功能。
4. 叠加角度曲线，圈出“过零后继续往另一侧走”的片段，为过冲和振荡命名。不要把偶然的一次过零称为持续振荡。
5. 打开请求力与实际力两条曲线，找到请求 `12 N`、实际 `10 N` 的时刻，解释输出饱和。
6. 换一个预先公布的非零初始条件重复排名，观察“最好的一组参数”是否仍最好。
7. 让学生给下一课留下一个需求：“只看角度，尚不知道它正倒得多快。”

**学生模板与新增 Python 内容**：控制函数继续使用 L13；在记录练习中第一次使用列表和循环，先处理已有结果，不要求学生手写整个仿真循环。

```python
# 由教师解释：列表保存要试的值，循环逐个读出。
gains_to_try = [0.0, 20.0, 40.0, 60.0, 100.0]
for kp in gains_to_try:
    print("这次准备测试 kp =", kp)
```

软件后续提供“用这些参数重复实验”按钮。不要把以上打印循环误称为已经实现了批量仿真。

**实验条件与对照**：主对照 `[0, 0, 0.05, 0]`；复核 `[0, 0, -0.03, 0.05]`。统一 ±10 N、0.02 s、12°、2.4 m、500 步。遇到提前终止记录原因，不补零冒充完整轨迹。

**常见误解**：最大增益不保证最好；推力饱和后继续加大 `kp` 不等于电机力量继续增大；一次试验排名不代表全部场景；短回合的角度 RMS 可能小，但它已经失败，不能只凭 RMS 判优。

**界面显示顺序**：动画与现有参数 → 一次只一条曲线 → 两组叠加 → 扫描表 → 请求/实际推力。高级绘图工具保持折叠。

**验收与产物**：提交 `l14_scan.csv` 和一个失败截图；能指出至少一次“更大增益没有改善某个指标”的实测结果，若没有观察到也应如实记录，不编造预期趋势。

**拟实现模块**：`evaluation/sweep.py` 复用场景和记录器；`evaluation/metrics.py` 增加饱和比例；`lessons/content/L14.json` 保存练习步骤，`lessons/templates/l14_scan.py` 提供列表练习。测试必须验证所有扫描项复用同一初始状态与配置。

## L15：看见倾倒速度——从 P 到 PD

**前置**：完成 L14，区分角度与角速度。建议 75–90 分钟。

**引导问题**：“两根杆都向右偏 3°，一根还在往右倒，另一根已经在往回走，应该同样用力吗？”

**课堂步骤**：

1. 并排暂停两次场景：角度均为 `0.05 rad`，角速度分别为 `+0.15` 与 `-0.15 rad/s`。学生用箭头表示下一瞬间的趋势。
2. 先运行 P，核对它对这两个状态给出相同的初始输出，理解缺少的正是变化速度信息。
3. 在 P 的代码上只增加 `kd * omega` 一项。手算两种状态的输出差异。
4. 固定 `kp=60`，比较 `kd=0、4、8、12`；这组数只是扫描参考，是否稳定以记录为准。
5. 打开 P 与 D 的分项力，暂停观察 D 何时增加推力、何时减少推力。解释 D 在闭环中帮助阻尼，但它的符号不是“永远向左”或“永远反向”。
6. 对同一组练习种子比较 P 与 PD 的成功回合数、角度变化与最大小车位置；不要挑各自最漂亮的一次录像。
7. 保存最能解释现象的一对轨迹，用口头说明替代背诵公式。

**学生代码**：

```python
kp = 60.0
kd = 12.0  # 单位 N·s/rad；参考起点

def control(state, dt):
    p_force = kp * state["theta"]
    d_force = kd * state["omega"]
    return p_force + d_force
```

**实验条件与对照**：先使用上述两种精确状态，再使用相同 seeds `42–46`。对照只改变 `kd`；保持 `kp`、动作模式、阈值、力上限一致。这里直接使用环境提供的角速度，不要求学生先学习数值微分。

**常见误解**：D 不是另一个角度系数；`omega` 已经是每秒的变化量，不能再除以 `dt`；直接角速度反馈避免了差分计算，却不意味着未来真实传感器没有噪声；PD 站得住不保证小车回到中央。

**界面显示顺序**：两幅相同角度不同运动趋势的动画 → 角速度箭头 → 两行代码 → P/D 分项 → 对照曲线。

**验收与产物**：学生能判断上述两个状态哪一个应有更大的正向推力；保存 `l15_pd.py` 与一个公平对照报告。若未实现长期稳定，先检查符号与单位，不要求凭空继续加参数。

**拟实现模块**：`lessons/content/L15.json`、`lessons/templates/l15_pd.py`、控制分项显示组件、场景对照器。分项是控制器主动上报的教学数据；界面不得对任意学生代码猜测“哪部分是 P 或 D”。

## L16：杆站住了，小车为什么越走越远——回中反馈

**前置**：完成 L15，理解 `x/v`。建议 75–90 分钟。

**引导问题**：“保持杆直立和让小车停在中央，是不是同一个目标？”

**课堂步骤**：

1. 运行纯角度 PD，选择具有非零小车速度或位置偏差的场景，观察角度较小但小车仍漂移的片段。
2. 把中央画成一个较宽的目标区域，区分“杆没倒”和“小车已经回中且速度小”两项指标。
3. 教师提供现有参考完整反馈 `60θ + 12ω + 2x + 3v`，先观看全过程，再允许学生修改。
4. 在 `x=+0.2 m、其他状态=0` 处单步观察。说明本参考先产生正力，底座运动使杆产生倾斜，角度反馈再参与调整；必须从整套耦合过程理解回中。
5. 比较纯角度 PD、PD 加 `2x`、PD 加 `2x+3v`，其余条件不变。记录前 0.2 s 的短期动作和整段轨迹，避免只看第一帧就判断方向错。
6. 由教师给出一个过大的回中增益示例，观察回中愿望与保杆能力之间的冲突。学生只在公布的小范围内一次调整一项。
7. 学生用两句话解释“车的位置目标”和“杆的角度目标如何互相影响”，不要求推导极点或状态空间矩阵。

**学生代码**：

```python
def control(state, dt):
    balance = 60.0 * state["theta"] + 12.0 * state["omega"]
    centering = 2.0 * state["x"] + 3.0 * state["v"]
    return balance + centering
```

**实验条件与对照**：`[0.2, 0, 0, 0]` 与 `[0, 0.1, 0.02, 0]` 是拟新增教学场景；再用种子集复核。统一环境，不把单纯角度 PD 的失败归咎于学生“没有理解 PID”。上述增益仅对应当前参考模型。

**常见误解**：不要直接把普通独立小车的 `-Kx*x-Kv*v` 拼到这里；增益符号来自整个被控系统，不能靠“反馈必须写减号”判断；回中瞬间杆有小角度不一定是控制失败；本课仍未包含大角度起摆。

**界面显示顺序**：中央目标区 → 小车位置曲线 → 速度曲线 → 回中分项 → 与角度 PD 对照。首次只显示“保杆”和“回中”两个模块，避免四个滑杆一起出现。

**验收与产物**：保存 `l16_centering.py`；提交纯 PD 与完整反馈在相同场景下的轨迹；能说明增益选择只在给定模型及测试条件下成立。评分看证据和解释，不硬性要求某个尚未验证的秒数回中。

**拟实现模块**：`lessons/content/L16.json`、`lessons/templates/l16_centering.py`、目标区域覆盖层、`metrics.final_x/final_v`。回中稳定时间属于新增指标，需在开发时明确容差和持续窗口，不能只取一次穿过中央的时刻。

## L17：一直差一点怎么办——用单车速度场景认识积分 I

**前置**：完成 L16，会赋值与四则运算，认识误差。建议 75–90 分钟。

**重要边界**：0.2.0 已提供独立的单车速度场景，用于讲解速度 PI。它使用明确的单车动力学，不属于倒立摆正式比较协议；不能把它的成绩与倒立摆成绩放在同一张排名表里。

**引导问题**：“有一股持续向左的力时，为什么速度总比目标低一点？可以把过去没追上的部分记下来吗？”

**场景规格**：水平单车质量 `m=1 kg`，粘性阻力 `b=0.5 N·s/m`，已知恒定偏置力 `F_bias=-0.5 N`；运动方程 `dv/dt=(u-b*v+F_bias)/m`，步长仍为 `0.02 s`。目标速度先设 `0.3 m/s`，推力限幅仍为 `±10 N`。轨道应允许平移浏览，不因持续行驶在 `2.4 m` 处结束；界面清楚标出这是速度实验台。参数及积分法都写进实验配置。

**课堂步骤**：

1. 固定杆不再摆动，只显示目标速度线和实际速度。先用恒定推力感受持续负载的影响。
2. 写普通速度比例控制 `u=Kp*(target_v-v)`，比较无偏置与有偏置两种条件。说明本场景的误差符号与此前角度规则不同，是因为被控对象不同。
3. 停在速度基本不再变化时，读出目标与实际之差；教师把“持续的差距”命名为稳态误差。
4. 用纸上三步练习计算 `integral += error*dt`，例如同样 `0.1 m/s` 的误差持续 `0.02 s` 与 `0.2 s`，积累量不同。
5. 在函数外加入积分变量，保留前一次调用后的值；先只打印或显示积分，不把它加入推力。
6. 增加 `ki*integral`，比较 P 与 PI 在同样偏置下的变化。参考起点 `Kp=2、Ki=1`，由教师预运行确认课堂现象，不声明适合倒立摆。
7. 回到倒立摆参考实现，说明默认 `Ki=0` 的原因：积分解决的是特定问题，不能把单车速度课的结论照搬为“所有平衡都需要 I”。

**学生代码：仅用于拟新增单车速度实验台**：

```python
integral = 0.0
target_v = 0.3
kp = 2.0
ki = 1.0

def reset():
    global integral
    integral = 0.0

def control(state, dt):
    global integral
    error = target_v - state["v"]
    integral += error * dt
    return kp * error + ki * integral
```

这里的 `reset()` 是 0.2.0 统一控制适配器已支持的可选钩子。回合重置时清空积分等记忆，暂停/继续保留状态；教师应检查学生代码是否实现了正确的重置内容。

**实验条件与对照**：每次 `v=0`、积分为零，运行同样时长；比较 P/PI × 偏置力 0/-0.5 N，共四格。保持质量、阻力和目标速度一致。无偏置时仍有粘性阻力，不能把“无偏置”误称为“完全无负载”。

**常见误解**：积分不是把误差简单加很多次，必须乘 `dt`；积分变量放在 `control()` 内每次赋零就不会积累；把 `dt` 写成窗口刷新间隔会改变结果；PI 的目标速度稳定后小车继续移动是正确行为。

**界面显示顺序**：目标/实际速度 → 当前误差 → 历史误差面积动画 → 积分值 → P/I 两项力。不要把大幅积分曲线默认盖在速度曲线上。

**验收与产物**：完成一次手算积分；保存 `l17_velocity_pi.py` 和四格对照表；能说明何时值得试 I，何时不能断言 I 有益。

**拟实现模块**：`envs/cart_velocity.py`、`lessons/content/L17.json`、`lessons/templates/l17_velocity_pi.py`、`inputs/adapters.py` 的可选 `reset` 支持。增加动力学量纲与恒定负载测试；课程加载时必须明确 `scenario_id=cart_velocity`，禁止误选倒立摆。

## L18：力量已经用尽，为何还在积累——积分饱和与条件积分

**前置**：完成 L17，理解请求推力与实际推力。建议 60–75 分钟。

**引导问题**：“已经踩到底，速度仍追不上；之后把目标降下来，为什么还会继续往前冲？”

**课堂步骤**：

1. 延续单车速度实验台，明确把本课推力上限暂改为 `±1 N`，与正式倒立摆的 `±10 N` 区分。
2. 目标速度在前 4 秒设为 `4 m/s`，随后降至 `0.3 m/s`。按 L17 的阻力和偏置，前半段目标超出持续推力能力，后一目标在能力范围内。
3. 先运行没有保护的 PI，观察请求力超过实际力时积分还在增长。只改变目标时刻，不改变初始状态。
4. 学生预测目标降低后 I 项还保留什么“记忆”，再观看实际曲线。
5. 先加入积分上限，解释它约束内部状态；再加入条件积分，解释“不再往饱和方向继续积累”。
6. 对比无保护、仅积分限幅、条件积分三种方案，记录降低目标后的超调和恢复时间。
7. 恢复正式推力上限并回看参考倒立摆控制器的条件积分代码，明确其 `Ki=0` 时会清零积分，保护机制可以存在但并未实际启用 I。

**核心模板：教师逐行拆解，不要求第一次整段默写**：

```python
integral = 0.0
elapsed = 0.0
kp, ki = 2.0, 1.0
force_limit = 1.0  # 仅本课速度场景
integral_limit = 1.0

def reset():
    global integral, elapsed
    integral = 0.0
    elapsed = 0.0

def control(state, dt):
    global integral, elapsed
    target_v = 4.0 if elapsed < 4.0 else 0.3
    error = target_v - state["v"]
    candidate = max(-integral_limit,
                    min(integral_limit, integral + error * dt))
    request = kp * error + ki * candidate
    unsaturated = abs(request) <= force_limit
    helps_recover = request * ki * error < 0.0
    if unsaturated or helps_recover:
        integral = candidate
    elapsed += dt
    return kp * error + ki * integral
```

环境负责实际执行力限幅。`request` 是使用候选积分计算的请求力；条件里的乘积用于判断本次积分变化是否有助于从饱和中退出。先用正饱和和负饱和各一个数值例子解释，避免让学生把布尔表达式当口令背诵。

**实验条件与对照**：三组均从同样状态运行 12 秒，目标变化时刻统一；目标时间线写入配置。无保护组不截断积分；仅积分限幅组和条件积分组使用 `integral_limit=1.0`（误差单位m/s，积分单位m）。规划阶段独立数值探针已验证本场景可触发该限幅；原候选20不会触发限幅，已舍弃。进入GUI课堂前仍需预运行并固定展示数据，这不是其他模型的通用参数。

**常见误解**：输出限幅不会自动限制积分；积分限幅和条件积分解决的问题有关但并不相同；目标超出物理能力时任何调参都不能保证达到；条件积分也不是对所有控制器都足够的万能方案。

**界面显示顺序**：先显示推力限幅标记 → 请求/实际推力分离 → 积分曲线 → 目标变化指示 → 三方案叠加。保留“恢复 ±10 N 正式配置”的明确操作，不能让限幅修改悄悄污染后续课程。

**验收与产物**：能在轨迹上圈出发生饱和与冻结积分的区间；提交 `l18_anti_windup.py` 和三方案对比。若恢复时间计算条件未满足，显示“本回合未恢复”，不能显示 0 秒。

**拟实现模块**：`lessons/content/L18.json`、`lessons/templates/l18_anti_windup.py`；复用饱和记录器，新增 `ScenarioConfig.target_schedule`、控制器诊断中的积分值与冻结标志。测试正/负饱和、误差反向解饱和、`Ki=0` 三类边界。

## L19：让程序拥有记忆，也能重新开始——完整控制器与重置

**前置**：完成 L18，认识积分和函数外状态。建议 75–90 分钟。

**引导问题**：“第二次实验，为什么可能带着第一次的积分或滤波记忆开始？”

**课堂步骤**：

1. 教师故意不清零积分，连续运行两回合，让学生发现相同初始条件却得到不同输出。
2. 列出需要跨步保存但回合开始应清空的内容：积分、上一观测、滤波器状态、仿真时间；对比无需每回合改变的增益配置。

7. 一次运行多个回合并保存快照，尝试从保存的代码和配置复现实验。

**倒立摆短函数参考模板**：

```python
kp, kd, ki = 60.0, 12.0, 0.0  # 默认不启用积分
cart_kp, cart_kd = 2.0, 3.0
integral = 0.0
integral_limit = 0.5
force_limit = 10.0

def reset():
    global integral
    integral = 0.0

def control(state, dt):
    global integral
    error = state["theta"]
    p = kp * error
    d = kd * state["omega"]
    cart = cart_kp * state["x"] + cart_kd * state["v"]
    candidate = max(-integral_limit,
                    min(integral_limit, integral + error * dt))
    requested = p + d + cart + ki * candidate
    if ki == 0.0:
        integral = 0.0
    elif abs(requested) <= force_limit or requested * ki * error < 0.0:
        integral = candidate
    return p + d + cart + ki * integral
```

**可选类接口练习**：先完成短函数版本再做；类不是理解 PID 的先决条件。

```python
class Controller:
    def __init__(self):
        self.reset()

    def reset(self):
        self.integral = 0.0

    def act(self, observation, dt):
        x, v, theta, omega = observation
        # 从上面的短函数迁移；不要在 act() 里重新创建 Controller。
        return 60.0 * theta + 12.0 * omega + 2.0 * x + 3.0 * v
```

上面类例子只示范生命周期与观测转换，没有启用积分；学生迁移积分逻辑时把 `integral` 改成 `self.integral`，并保留条件积分。本例 `integral` 暂未使用，教师应明确指出，不让学生误以为它已是 PID。

**实验条件与对照**：用同样 seed 连跑两次，检查重置后首状态、首动作一致；再用不同 seed 确认并非硬编码轨迹。保留错误重置案例作为课堂素材。

**常见误解**：每个 `control()` 调用都创建新对象会丢失记忆；Python 全局变量需要通过 `reset()` 与场景重置同步；暂停/继续应保留状态，重新开始应清空，二者不同。0.2.0 正式 CLI 评价可直接加载短函数文件。

**界面显示顺序**：本回合计数 → 状态记忆小卡片 → 重新开始前后对照 → 代码保存 → 批量执行。普通学生默认继续使用短函数，类接口放进“想了解工程写法”展开区。

**验收与产物**：提交一个可重置的控制器和两次一致的复现报告；说明暂停与重新开始的差别。进阶学生额外交付类版本，基础学生不因未学类被扣分。

**拟实现模块**：`lessons/content/L19.json`、`lessons/templates/l19_stateful.py`；`inputs/adapters.py` 同时支持短函数与现有类协议；`desktop/engine.py` worker 增加回合重置消息；`runner.py` 复用适配器。测试每回合恰好重置一次、暂停不重置、重置异常保存报告、学生代码超时不冻结 UI。

## L20：真实读数会抖——噪声、滤波和微分冲击

**前置**：完成 L19，理解角速度反馈、`dt` 和持久状态。建议 75–90 分钟。

**引导问题**：“杆没有明显乱晃，为什么计算出来的推力却在快速跳动？”

**课堂步骤**：

1. 固定同一个已能运行的完整反馈控制器，先保存无噪声对照。
2. 仅给控制器读到的角度加入可复现小噪声，真实物理状态与终止判定不加噪声；同时显示“真实值”和“传感器读数”。
3. 运行并保存角度测量噪声实验；打开右侧“信号实验”页签，在“同一份数据，换一种看法”中选择保存目录的 `trajectory.csv`，点击“分析同一条轨迹”并打开曲线报告。对照直接 `omega`、`(theta-last_theta)/dt` 与因果滤波，移动鼠标读同一时刻的数据；改变分析面板的 `tau` 重算同一文件。先完成离线对照，再把控制器的 `omega_source` 改为 `difference` 作闭环观察，避免把反馈造成的轨迹差异误当测量噪声差异。
4. 选择“角速度测量噪声”场景，控制器设 `omega_source="sensor"`，依次修改代码中的 `tau=0、0.02、0.05、0.1 s`，分别运行并保存四轮实验。`tau=0` 表示不滤波，其余取值是待验证扫描，不保证越大越好；分析面板的 tau 只影响离线报告，不会自动改写控制代码。
5. 对比推力变化和响应迟滞，解释滤波会付出延迟代价；默认由学生选择一个折中并保存失败例子。
6. 点击“运行目标跳变实验”并打开报告：目标在 1 s 从 0 跳到 `0.02 rad`，测量角度始终为 0，`dt=0.02 s、Kd=12`。用游标对照误差求导的 `-12 N` 尖峰与仅测量求导的 `0 N`，再改变 tau 观察峰值降低和拖尾。此步骤只计算信号，不运行倒立摆、不施加 ±10 N 限幅，不把信号结果当回中成绩。
7. 恢复正式无噪声协议，保存带噪声实验为单独鲁棒性协议，防止后续排名混入不同条件。

**滤波模板：本例使用噪声包装器提供的测得角速度**：

```python
import math

filtered_omega = None
tau = 0.05

def reset():
    global filtered_omega
    filtered_omega = None

def control(state, dt):
    global filtered_omega
    measured = state["omega"]
    if filtered_omega is None:
        filtered_omega = measured
    alpha = 1.0 if tau == 0 else -math.expm1(-dt / tau)
    filtered_omega += alpha * (measured - filtered_omega)
    return (60.0 * state["theta"] + 12.0 * filtered_omega
            + 2.0 * state["x"] + 3.0 * state["v"])
```

使用已提供的指数公式，使模板、离线实验与软件 `FirstOrderLowPass` 一致；学生本课只需调整时间常数，无需先推导离散化。完整模板还提供 `omega_source="difference"` 和 `last_theta/reset()`，差分控制首步暂用 0，报告首样本标为未知并排除差分指标。

**VS Code 操作入口**：导出的 `l20_exercise.py` 可作为控制器，也可在终端运行下列独立实验。每次输出目录必须是新目录，已有结果不会被覆盖。命令中的轨迹路径替换为自己的保存记录，`--tau` 只设置这次离线分析。

```powershell
python l20_exercise.py noise --trajectory "已保存实验/trajectory.csv" --output-dir "实验结果/l20-noise-01" --tau 0.05
python l20_exercise.py kick --output-dir "实验结果/l20-kick-01" --dt 0.02 --tau 0.05
```

每个结果目录包含 `signals.csv`、`report.json`、无需联网的 `report.html`。程序支持课堂记录的 `simulation_time_s`；评价记录的 `time_s` 对应动作后状态、观测却在动作前，因此会向前对齐真值，首个缺失真值不参与误差统计。差分噪声通过“带噪角度差分减去同一真实角度差分”单独计算，与对真实角速度的总误差分别报告；前者不包含有限差分本身的近似误差。拒绝跨回合、丢步、错误 dt 的记录，不能用未来样本平滑。

**微分冲击的符号说明**：按本课程误差 `error=theta-target_theta`，若对误差差分，目标突然增加会引入一个负的尖峰项；若只使用测得的 `omega`，不会直接把目标阶跃求导。两者都可能有测量噪声，不能把“无目标微分冲击”等同于“无噪声”。

**实验条件与对照**：噪声只影响控制器观测，真实值始终单独记录。课堂可从角度标准差 `0.002 rad`、角速度标准差 `0.02 rad/s` 开始逐个启用，独立噪声 seed 固定，不与初始状态 seed 混在一起。给所有算法相同的噪声时间序列；滤波状态每回合清零。

**常见误解**：曲线变平滑不等于控制变好；差分角度时忘除 `dt` 或把 `omega` 再除一次都不对；不能用未来样本平滑后再声称可实时控制；真实状态与测量状态的终止判定不能混淆。

**界面显示顺序**：原始曲线 → 测量噪声开关 → 差分演示 → 滤波后曲线 → 推力变化 → 高级目标阶跃演示。多个噪声开关不同时默认开启。

**验收与产物**：提交 `l20_exercise.py`、同输入分析的 CSV/JSON/HTML、独立目标跳变报告；解释一种滤波收益和一种代价；给出无噪声/有噪声、无滤波/有滤波的对照表，至少保留一个不理想配置。软件只验证实际报告已生成，不自动判定学生的物理解释正确。

**实现模块**：`controllers/filters.py`、`lessons/signal_experiments.py`、`desktop/panels/signals.py`、`lessons/content/L20.json`、`lessons/templates/l20_exercise.py`；真实/观测和噪声 seed 由公共场景/记录层保存。终止只依真实状态，评分分别列理想协议与噪声协议。离线分析不写控制器评分。

## L21：用同一把尺评价——传统控制公平比较

**前置**：完成 L20，知道代码、参数和环境都影响结果。建议 75–90 分钟。

**引导问题**：“A 动画看起来更漂亮，B 活得更久，究竟该怎样比较？”

**课堂步骤**：

1. 展示一个故意不公平的对比：A 用 80° 阈值，B 用 12°；让学生找出不能直接比较的原因。
2. 逐项核对正式协议：动作是 N、±10 N、0.02 s、12°、2.4 m、500 步，同样 20 个非零初始回合，默认无噪声无外扰。课堂先在开发验证集 `100–119` 学会比较；最终交付评分才使用保留种子 `10042–10061`。
3. 选择零输入、P、角度 PD、PD 加回中、个人方案。名称同时展示真实启用项；`Ki=0` 的参考显示“PD + 回中（Ki=0）”。
4. 先评估零输入基线，确认这批初始条件不是全部零状态；再批量评估其他控制器。
5. 先看是否失败与失败原因，再看成功率、回合长度分布、角度 RMS、最大 |x|、实际用力和饱和比例。学生学习用多个指标描述权衡。
6. 随机选择一个成功与一个失败回放；检查代码快照、协议哈希与模型参数，证明比较可以复现。
7. 写三条结论：给定条件下谁表现较好、付出了什么代价、还有什么没测试。给后续 RL 留下完全相同的基线报告。

**指标定义建议**：

| 指标 | 定义及解释 |
| --- | --- |
| 通过回合比例 | `未因角度/位置终止且完成500步` 的回合数 / 总回合数；到达时限只表示通过这段测试 |
| 存活时间 | 实际物理步数 × 0.02 s；报告均值及最短值，必要时列分位数 |
| 角度 RMS | 在该回合已有状态上计算，单位 rad；提前失败回合单独标注，不因数据短而拿小 RMS 宣称更优 |
| 绝对位置最大值与最终位置 | 反映越界风险和回中情况；不直接等价于杆的稳定性 |
| 平均绝对实际推力 | `mean(abs(applied_force))`，单位 N；是用力指标，不是能耗 |
| 饱和比例 | 请求力超过限幅的控制步数 / 已执行步数；可另列实际力贴近上限比例，定义需区分 |
| 推力变化量 | `mean(abs(u[k]-u[k-1]))`，单位 N/步；不是 jerk，也不是物理能量 |

如后续需要功或能量，需定义 `力 × 速度` 的功率与积分方式，并处理负功；不能把 `sum(u*u)` 标注为焦耳。

**常见误解**：平均分不能遮盖频繁失败；只运行训练时见过的种子不等于泛化；500 步通过不证明永久稳定；目标速度模式包含额外反馈，不能无说明地加入纯推力排名；改变阈值后仍沿用旧协议名称会使历史比较失效。

**界面显示顺序**：协议确认页 → 基线运行 → 批量进度 → 成功/失败概览 → 详细指标 → 轨迹回放。错误与超时显示为错误，不能记成普通环境失败或零分后静默跳过。

**验收与产物**：提交一个至少包含 3 种方法、20 个相同回合的对照包，包括代码快照、协议、CSV、JSON 和结论；能够现场复现指定 seed。验收先检查公平性，再检查表现。

**拟实现模块**：`lessons/content/L21.json`、`evaluation/protocols.py`、`evaluation/batch.py`、`evaluation/metrics.py`、`evaluation/report.py`；复用 `runner.py` 的快照与轨迹功能。测试同协议同种子同控制器结果一致、异常报告不中断其他方法、成功判据区分 `terminated/truncated`。

## L22：我的第一个控制项目——交付、解释与展示

**前置**：完成 L21，能够保存与复现个人代码。建议 120–150 分钟，可拆成两课。

**引导问题**：“如果把代码交给没听过你讲解的同学，他能重现实验并理解你的取舍吗？”

**课堂步骤**：

1. 从任务卡选择一个明确目标：优先减小摆角、优先减少小车漂移、优先减少推力抖动。所有目标都先满足同一个基本平衡与边界条件。
2. 写下基线、准备修改的唯一部分、预期影响和可能代价。例如“在角度 PD 上增加回中项，可能减少漂移，也可能增大短时摆角”。
3. 用 `42–46` 练习，并用 `100–119` 开发验证，保留每次修改记录；不在最终评分种子集上反复挑最佳参数。
4. 冻结代码与参数，运行正式协议；如果失败，提交失败证据和修正假设，允许重新学习，但不得把失败记录删除后只呈现最好一回合。
5. 加选一个独立的鲁棒性扩展：噪声、初始偏差、已公布外扰之一。一次只加一种变化，并使用新的协议名称。
6. 导出项目包，把 README、源码、参数、协议、报告、轨迹和一段简短回放放在一起；请另一位同学按说明复现。
7. 完成 3 分钟讲解：程序看见什么、如何决定用力、在哪些条件下工作、一个失败例子、下一步如何改进。
8. 以“人的规则能做到这些，能否让程序自己改进规则”引入下一阶段强化学习，不贬低传统控制，也不暗示 RL 必然更优。

**学生报告模板**：

```text
项目名称：
控制目标和边界：
观测与输出单位：
控制公式/关键代码：
为什么这样选符号：
基线与我只修改的一项：
练习协议、正式协议及版本：
20回合结果与失败原因：
一个成功例子 / 一个失败例子：
重复运行方法：
当前限制和下一步问题：
```

**实验条件与对照**：正式成绩沿用 L21；扩展实验单列，不拿宽松阈值成绩替换正式成绩。鲁棒性外扰必须通过拟新增场景配置定义作用时刻、持续时长、力或速度冲量及其单位，不能依靠教师随机拖动鼠标制造“同样扰动”。

**常见误解**：项目不要求 `Ki` 必须非零；参考代码允许作为基线但需要标注；漂亮动画不能替代实验配置；评价重点是可复现且能解释，不是把增益调整得与参考数字不同。

**界面显示顺序**：任务卡 → 个人实验计划 → 参数与代码 → 练习记录 → 冻结提交 → 正式报告 → 展示模式。完成报告前不要弹出未经证据支持的“已掌握 PID”徽章。

**验收与产物**：提交 `l22_project/`，至少包括控制代码、README、配置、报告和可复现运行记录。建议评分：实验公平与记录 30%，解释符号/状态/重置 25%，控制效果与失败分析 25%，同伴可复现性 20%；控制效果不应淹没其余能力。具体性能门槛先由教师参考方案跑出基线，再向学生公布。

**拟实现模块**：`projects/export.py` 导出学习成果，`lessons/content/L22.json` 保存任务卡和量规；导出只打包用户明确选择的课程工作区文件，不遍历个人磁盘。下一章读取相同 `EvaluationProtocol` 比较 RL，不复制一套新的评分代码。

### 控制器执行时序：教学 GUI 与正式评估需分别定义

0.2.0 GUI 异步运行学生代码，但等待当前步骤对应的动作返回后才推进物理一步，不沿用上一动作补跑。正式评估同样逐步应用观测对应动作；计算慢可以让实验使用更多墙钟时间，不改变 `dt`。

后续需采用“请求动作 → 动作返回 → 推进一步”的确定时序，同时让 GUI 事件循环与取消操作保持响应。超过执行期限时标记控制器超时并保存记录，不把无穷等待计作正常倒杆。高级章节若有意研究计算延迟，应另建显式含延迟的协议，并为所有被比较算法使用同样规则。

### 新增数据至少需要保存的字段

- 实验身份：课程 ID、场景 ID、环境/软件版本、协议 ID 及哈希、代码哈希。
- 可复现条件：初始状态、初始 seed、噪声 seed、控制参数、物理参数、外扰计划、目标计划。
- 每步状态：步号、仿真时间、真实四维状态、控制器观测、请求力、实际执行力。
- 可选诊断：P/I/D/回中分项、积分值、饱和与冻结标志；未上报就显示“未提供”，不可捏造。
- 结果：执行步数、环境终止/时限通过/代码错误/用户取消/控制超时、指标及原始轨迹位置。

这些字段由公共执行层与记录器生成，学生从 L13 到 L22 不必逐课重新写保存 CSV 的样板代码。
