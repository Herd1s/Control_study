# 从第一次拖动到强化学习

本文保留原始教学主线概要与设计意图。0.2.0 当前实现与限制见 [实现审计](IMPLEMENTATION_AUDIT.md)，使用命令见 [README](../README.md)。[32课路线图](ROADMAP.md)、[逐课教案](curriculum/01_FOUNDATIONS.md) 和 [代码规划](DEVELOPMENT_PLAN.md) 细化各阶段，不代表每项原始需求都已经验收。

这套课程面向没有编程、控制或机器人基础的学生。先让学生看到、操作到，再为已经经历过的现象命名。Python在解决眼前小任务的过程中引入，不要求先完成一整门编程课。

以下是完整教学路线。0.1.0 首先实现“亲手试试、看见变化、第一段代码”；0.2.0 已增加传统控制面板、32 课资源、正式评价和独立强化学习入口。外部环境要求与仍需教师手动验收的活动在实现审计中注明。

## 第一阶段：用手接住杆

**学生任务：** 用鼠标拖动中间的小车或滑块，尽量让杆保持站立。先自由尝试，再观察“往哪个方向移动更容易接住它”“移动太快会发生什么”。失败后能够立即重试。

点击“重新扶正”后，小车居中、摆杆完全竖直且静止。理想模型在没有输入和扰动时会保持这个状态，学生拖动小车后开始体验平衡。

**界面内容：** 中央动画、简短操作提示、暂停和重试按钮。第一课操作区不讲公式、PID、参数表或代码；侧边导航仅标出后续课程路线。

**教师引导：** 先让学生说出自己的发现，不立即介绍控制理论。可以让同学轮流尝试，比较提前动作与倒得很快后才动作的差异。

**完成标准：** 学生能用自己的话描述一种有帮助的操作和一种容易失败的操作，不要求首次就长期稳定。

## 第二阶段：把肉眼判断变成可测量信息

**学生任务：** 继续亲手操作，同时逐项认识四种信息。先说中文含义，再出现变量名和单位。

| 先理解的问题 | 可测信息 | 后续代码中的名称 |
| --- | --- | --- |
| 小车现在在哪里？ | 小车位置，m | `x` |
| 小车正在向哪边、以多快速度移动？ | 小车速度，m/s | `v`或`x_dot` |
| 杆偏向哪边、偏了多少？ | 倾斜角；界面为°，代码为rad | `theta` |
| 杆正在向哪边、以多快速度倾倒？ | 角速度；界面为°/s，代码为rad/s | `omega`或`theta_dot` |

**界面内容：** 保留动画，逐步增加读数和方向提示。讲解角度时再介绍零点与正负方向，不把所有单位和符号一次塞给学生。

**教师引导：** 暂停在两个角度接近、倾倒速度不同的时刻，让学生判断是否应该采取相同动作。再说明程序需要哪些信息才能代替眼睛。

**完成标准：** 能把四种读数对应到动画现象，能说明“当前角度”和“正在倾倒多快”不是同一个信息。

## 第三阶段：写第一段会动的Python

**学生任务：** 从修改一个数字开始，让程序产生可见动作。先试固定正值、零和负值，再引用一个观测变量，最后写一个简单的条件判断。

建议按以下小步组织练习，每步都立即运行动画：

1. **数字和方向。** 改动输出数字，观察小车向左、向右或保持零输入。
2. **变量。** 读取杆的角度，试着让输出随角度变化。
3. **计算。** 将读数乘以一个系数，比较系数不同的效果。
4. **条件。** 按倾斜方向选择动作，用条件判断表达自己的手动经验。
5. **函数。** 理解软件会反复询问“这一次该怎么做”，自己的代码需要返回一个答案。

**两种指令先选一种教：** 推力的单位是N，目标速度的单位是m/s。目标速度较贴近“让小车往这边移动多快”的直觉；推力更直接对应后续物理控制。软件可以提供两种练习，但每次必须显示当前模式，不能把相同数字当成同一种动作。

**界面内容：** 简短代码、当前输入和结果；语法错误用能够定位问题的提示呈现。不要要求新手一开始就理解包结构、环境安装和完整控制器类。

桌面课堂的代码入口是 `control(state, dt)`。先让学生只改 `return` 后的数字，再逐步认识 `state["theta"]` 等读数。模式设为推力时，下面的程序返回向右的1 N推力：

```python
def control(state, dt):
    return 1.0
```

输入字典提供 `x/v/theta/omega`，分别对应前一阶段的四种信息。目标速度模式下同一返回值表示1 m/s，由软件的内部速度反馈环转换为推力，教师应明确讲出这层帮助。进阶的 `Controller.reset/act` 类接口留到学生需要长期保存积分或批量评估时再介绍。

在VS Code中可编辑 `examples/first_action.py`，使用 **Python：我的第一段控制** 调试配置加载到 Python 入门课 L05，再点击界面运行。编辑保存后重新加载。0.2.0 的正式评价同时接受短函数与旧 `Controller` 类，进阶组织代码可参考 `examples/my_controller.py`。

**完成标准：** 不照抄整个算法，独立修改一小段代码产生预期方向的运动，并解释其中一个变量和一个条件。能让小车动起来就完成了本阶段，不要求平衡成功。

## 第四阶段：把经验写成P和PD

学生已经观察过“倒得越多，可能需要动作越大”。此时才把这种规则命名为比例反馈P。通过改变一个系数，观察响应和振荡，不先推导完整传递函数。

之后回到第二阶段的发现：即使角度相同，倾倒速度不同也需要不同动作。把角速度加入规则，再命名为微分反馈D。对比只用角度与同时使用角度、角速度的结果。

教学中先统一符号。若误差取 `theta - 0`，杆向右偏时应向右推小车去接；若改为“目标减测量”，输出方向也要同步调整。物理步长为0.02秒，不能用窗口刷新耗时替代。

**完成标准：** 能解释P和D分别依据什么信息，知道一次只改一个参数，并保留一组可重复的对照结果。

## 第五阶段：理解积分、饱和和回中

先提出具体问题：推力已经达到上限还不断积累误差，会发生什么；杆站住了，小车为什么仍可能漂走。用这些问题引入积分、抗饱和以及位置、速度反馈。

在完整Python控制器中实现积分状态，理解每步按“误差乘时间”累积，并在每回合重置。可以增加明确记录的常值偏置，比较是否需要积分；理想无偏置模型中，积分不一定改善效果。

参考控制器默认积分系数为零，实际为角度PD加位置、速度反馈。不能因为课程名称叫PID就要求学生把三个系数都设成非零。

**完成标准：** 能解释积分状态为什么要重置、什么是输出饱和，并从轨迹中区分杆角不稳与小车漂移。正式评估时比较回合长度、角度误差、小车位移和用力。

## 第六阶段：让程序通过尝试学习

从学生已经写过的程序过渡：此前由人决定控制规则，现在让程序通过多次尝试改进规则。先对应已有经验解释观测、动作、奖励、回合和策略，再介绍训练与评估。

先看随机动作，再使用支持连续动作的强化学习算法训练。训练和回放共用同一个物理环境，记录随机种子、配置和模型。已有离散CartPole策略不能直接用于这里，需要重新训练。

不要让复杂参数成为第一次训练的入口。0.2.0 的独立训练页先检查环境，再提供训练、停止保存、验证和回放；解释实验结果时仍应区分训练通路可用与策略已经稳定。

**完成标准：** 能说清楚程序从什么反馈中学习，能加载已保存策略重新评估，并知道训练中偶尔成功一次不能证明算法已经稳定。

## 第七阶段：用同一把尺比较方法

统一初始条件、终止阈值、动作含义、力限幅和评估时间，比较手写规则、PID与强化学习策略。当前桌面课堂的倒下阈值为80°、回合上限为500,000步；命令行默认为12°、500步。二者共享物理方程，但不能直接比较时长成绩。目标速度练习还包含内部速度反馈环，也需要统一或明确标注。

一次改变一个扰动或模型条件，记录成功与失败案例。达到500步只表示通过当前10秒平衡测试，不能据此声称能够稳定应对任意初始状态或实物扰动。

**完成标准：** 能用一张比较表和一个失败案例，说明各方法在给定条件下的表现，而不是只判断“哪个更高级”。

## 教师准备与建议节奏

课程可以按班级情况拆成短课，不要求所有学生在固定周数内完成。旧概要中的八周设想已由详细开发排期替代：按维护者每周6–8小时，核心课程与安装更新先规划24周、另留20%–30%缓冲；TITA选修从其后单独安排。每周任务、里程碑与门槛见 [开发路线图](ROADMAP.md)。这不是对零基础学生学习速度的要求，也不是完成时间保证。

每次试讲记录学生在哪里停住、误解了哪句话、需要看见什么反馈。先修正引导和操作，再增加更多算法。

从倒立摆迁移到TITA时，继续使用观测、动作、控制周期、饱和和评估这些概念，但重新理解机器人的关节与动力学；倒立摆代码和策略不能直接当作TITA控制器。
